# 配布用署名鍵（call5min-timer.jks）

アプリ内アップデートで自分自身を上書きインストールするため、Release APK は毎回この鍵で署名する。
鍵が変わると Android は更新を拒否する（同じ applicationId でも署名が違うとインストールできない）。

## 中身

| ファイル | 内容 |
| --- | --- |
| `call5min-timer.jks` | 固定の配布用キーストア（JKS / RSA 2048bit / 有効期限 10000 日） |
| `signing.properties` | 上のキーストアを開くためのパスワード・エイリアス |

`signing.properties` の値は `storePassword=call5min-timer` / `keyAlias=call5min` /
`keyPassword=call5min-timer`。

## リスクと前提（この鍵をリポジトリに置く理由）

この鍵は公開リポジトリに含まれている。つまり**誰でもこの鍵で APK に署名できる**。
この設計は SPEC §5.2 の要件（固定配布署名鍵で Release APK に署名し、アプリ内アップデートで
上書き更新する）に基づく意図的な選択で、次の前提の下で受けているリスクである。

- 配布は本人の GitHub Releases 経由のみ（ストア公開なし）。アプリの更新元は
  `yuushi-labs/call-5min-timer` の Releases に固定されていて、アプリが参照するのは
  ユーザー自身が管理するリポジトリだけ。
- 第三者が署名済み APK を作れても、それが自動更新として届く経路はない（Releases を
  上書きできないため）。手元に直接インストールさせる APK は、署名に関係なくユーザーが
  信頼するかどうかの問題になる。
- 将来的に配布対象を広げる場合は、鍵を CI Secrets へ移す。**同じ鍵（同じ署名証明書）を
  移すだけなら、保管先が変わっても既存インストールへの上書き更新は継続できる**
  （Android が確認するのは署名証明書であって保管先ではない）。上書き更新ができなくなるのは、
  鍵を**交換**する場合だけで、その場合は applicationId の変更か再インストールの案内が必要。

## 差し替え・再発行したくなったとき

この鍵を変えると、既存インストールへの上書き更新ができなくなる。変える場合は

1. `versionCode` を上げて別 applicationId にする、または
2. 一度アンインストールしてから入れ直す

のどちらかが必要になる。CI から署名する場合も、この鍵（または同じ鍵を Base64 にした
Secrets）を使うこと。
